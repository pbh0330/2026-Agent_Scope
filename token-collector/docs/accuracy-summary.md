# 도구별 토큰 귀속 — 계산 방법과 정확도 요약

10.13~10.29는 PC 실측(작성자 PC, OpenClaw 2026.9.5, 학교 게이트웨이 claude-haiku-4-5) 기준이다.
11.05는 테스트베드와 같은 조합(OpenClaw 2026.9.6, Anthropic API 직접 연결)으로 다시 쟀다(마지막 절).
날짜별 원본 기록은 작성자 개인 저장소에 백업했다(이 PR의 이전 이력).

## 계산 방법

도구 결과는 다음 모델 호출의 입력으로 들어간다. 그래서 "도구 하나가 쓴 토큰"을 다음 모델 호출 입력이 얼마나 늘었는지로 잰다.

| 구간 | 계산 | 근거 |
|---|---|---|
| 순차(모델 호출 사이에 도구 1개) | `다음 호출 입력 − 앞 호출 입력 − 앞 호출 출력` | OpenClaw 텔레메트리의 모델 호출 토큰(정확한 값) |
| 병렬·배치(모델 호출 사이에 도구 여러 개) | 구간 증가분 Δ는 위와 같이 정확히 구한다. 결과마다 고정분 k를 먼저 주고, 나머지(Δ − 결과 수 × k)를 플러그인이 결과마다 센 토큰 수 비율로 나눈다(11.06부터) | 플러그인 `token_count`(Anthropic count_tokens, 학교 게이트웨이는 `usage.prompt_tokens`) |
| 계산 못 함 | 결과별 토큰 수가 없거나 일부만 센 경우(이미지 등) | `null`로 두고 따로 셈. 0이나 균등 배분으로 채우지 않음 |

- 병렬 배분 값의 합은 항상 구간 증가분과 같다(최대 나머지 방식으로 정수 배분).
- k는 결과마다 붙는 고정 부분(도구 호출 ID·결과 태그 등)의 크기다. 같은 데이터의 순차 구간마다 (Δ − 플러그인 토큰 수)를 모아 모델별 중앙값으로 정한다.
  - 토큰 수 50 미만인 작은 결과와 차이가 음수인 구간은 표본에서 뺀다.
  - 순차 표본이 없으면 모델 기본값을 쓴다(Haiku 5.5 = 26). 기본값도 없거나 Δ < 결과 수 × k면 k 없이 토큰 수 비율로만 나눈다(10.29까지의 방식).
  - 쓴 k와 근거는 usage.json `limitations`에 적힌다.
- 비용은 귀속 토큰 × 입력 단가. PC 실측(학교 게이트웨이)은 단가가 0이라 Anthropic 공식 정가(참고용)로 계산했다. 테스트베드는 Anthropic API 직접 연결이라 같은 정가가 실제 단가다(그래도 캐시 할인 등을 빼지 않은 추정치).

## Anthropic API 직접 연결(11.05, OpenClaw 2026.9.6)

테스트베드와 같은 조합이다. 학교 게이트웨이와 달라진 점만 적는다.

- 캐시된 입력이 `input_tokens`와 따로 보고된다. `--include-cache-in-prompt`를 켜야 순차 공식이 맞는다(끄면 0으로 잘림).
- 결과마다 붙는 고정 부분이 학교 게이트웨이보다 크다(Δ − 플러그인 토큰 수: 학교 15~16, Haiku 4.5 30, Haiku 5.5 26).
  그래서 작은 결과의 병렬 배분 오차가 커진다.

| 모델·설정 | 순차 USER / AGENTS | 병렬 배분 | 순차 대비 |
|---|---|---|---|
| Haiku 5.5 직접 등록, thinking 지정 안 함 | 391 / 2,246 | 372 / 2,262, 373 / 2,271 | −4.9% / +0.7%, −4.6% / +1.1% |
| Haiku 5.5, `/think off` | 391 / 2,246 | 378 / 2,296(2회 같음) | −3.3% / +2.2% |
| Haiku 4.5, thinking off | 285 / 1,560 | 268 / 1,608(2회 같음) | −6.0% / +3.1% |
| Haiku 4.5, thinking Medium | 124 / 1,738 | 294 / 1,760 | 공식이 맞지 않음 |

- Haiku 4.5에서 thinking을 켜면 생각 토큰이 출력에는 잡히지만 다음 입력에는 들어가지 않는다. 그래서 순차 공식이 크게 어긋난다.
- Haiku 5.5는 이전 생각을 다음 입력에 포함하므로 거의 맞는다. 생각을 많이 한 구간 하나만 −66토큰(−2.9%) 어긋났다.
- 5.5를 9.6에서 쓰려면 thinking 수준을 지정하지 않아야 한다(지정하면 HTTP 400, `docs/testbed-setup.md` 3절).
- `/compact` 압축을 두 번 한 긴 세션에서도 순차 구간 고정분(26)과 병렬 결과가 그대로였다.
- 아주 작은 결과는 플러그인 토큰 수가 0 근처로 잘린다(exec "hello": 플러그인 0, Δ 10). 그래서 k 추정 표본에서 뺀다.

## 배분 방식 변경(11.06): 고정분 k를 먼저 줌

고정분까지 크기 비율로 나누던 방식(A)을 바꿨다. 결과마다 k를 먼저 주고 나머지만 비율로 나눈다(B).
B는 k = 0이면 A와 같고, 구간 합계 보존도 그대로다. 같은 데이터를 두 방식으로 다시 계산한 결과는 아래와 같다.

| 데이터 | k(자동) | A: 비율로만 | B: k 먼저 | 순차 실측 |
|---|---|---|---|---|
| 10.29 학교 게이트웨이 Haiku 4.5 | 16(순차 3) | USER 279~280, AGENTS 1,597~1,604, SOUL 422, fs 603 / 3,317 (최대 2.9%) | 290, 1,585~1,589, 430, 614 / 3,306 (최대 1.9%) | 286, 1,559, 423, 608 / 3,270 |
| 11.05 Anthropic Haiku 4.5 thinking off | 31 | 268 / 1,608 (−6.0% / +3.1%) | 290 / 1,586 (+1.8% / +1.7%) | 285 / 1,560 |
| 11.05 Anthropic Haiku 5.5(병렬 2개 ×6, 압축 전후) | 26(순차 7) | 372~378 / 2,262~2,296 (최대 −4.9%) | 391~396 / 2,243~2,278 (최대 +1.4%) | 391 / 2,246 |
| 11.05 Haiku 5.5 병렬 3개 | 26 | 376 / 2,285 / 550 (최대 −3.9%) | 393 / 2,255 / 562 (+0.4~0.5%) | 391 / 2,246 / 560 |

- 최대 오차가 2.9% → 1.9%(학교 게이트웨이), 4.9~6.0% → 1.4~1.8%(Anthropic 직접 연결)로 줄었다.
- 10.29의 SOUL.md처럼 A에서 우연히 거의 맞던 값(−0.2%)은 B에서 +1.7%가 됐다. 대신 결과 크기에 따라 한쪽으로 치우치던 오차는 없어졌다.
- Δ 자체가 틀어지는 경우(Haiku 4.5 thinking Medium: 316 / 1,738)는 B로도 고쳐지지 않는다. 테스트베드는 thinking 수준을 지정하지 않는다(`docs/testbed-setup.md` 3절).
- 10.29 데이터의 도구별 합계: read 11,805 → 11,790, ls 44 → 59, fs 3,920(변화 없음). 전체 15,769와 순차 2,268 / 배분 13,501은 같다.

## 소비 브레이크(10.29)

| 모드 | 설정 | 결과 |
|---|---|---|
| warn | 실행당 도구 호출 3회에서 경고 | 기록만 남고 실행은 그대로 |
| enforce | 3회 승인 요청, 5회 차단 | 3번째 호출 전 승인 창 → 허용 → 4번째는 다시 묻지 않음 → 5번째 차단, 에이전트가 차단 메시지를 보고 멈춤 |

- 병렬 호출은 결과가 오기 전에 실행 직전 검사가 한꺼번에 일어나, 결과 크기·토큰 기준은 다음 묶음부터 적용된다(호출 수 기준은 바로).
- 테스트베드에서는 `warn`으로 정상 사용 데이터를 모은 뒤 한도를 정한다(10.31 회의).

## 알려진 한계

- 텍스트 결과만 센다. 이미지가 섞인 결과가 있는 구간은 배분하지 않고 "계산 못 함"으로 둔다.
- 결과별 토큰 수를 세려면 모델 백엔드 키가 필요하다(플러그인 `apiKeyEnv`). 없으면 순차 구간만 계산된다.
- OpenClaw 2026.9.5에서 플러그인이 받는 trace id와 diagnostics-otel이 내보내는 trace id가 달랐다. 배분은 도구 호출 ID로 맞추므로 영향 없음. 테스트베드(2026.9.6)에서 다시 확인한다.
- 실행이 기록 중간에 끊기면 마지막 도구는 다음 모델 호출이 없어 계산되지 않는다(이후 기록으로 다시 계산하면 채워짐).
