## 실행 및 결과

11개 구성(P0/P1/P2/S1/S1-T5/S2/S3/S4/S5-T1/T2/T3)을 매회 새 출력·작업 디렉터리로 생성했다. 파이프라인은 세 번 모두 종료 코드 0이며 소요 시간은 각각 6.278초, 6.319초, 5.126초였다. 이 시간은 저장 자료 전체 파이프라인의 관측값이며 서버 수별 실시간 수집 성능(QA-NFR-01) 판정에 사용하지 않는다.

[독립 검사](../evidence/RUN-20261117-SAVED-01/checks.json)는 **179개 통과·0개 실패**, 별도 관찰 10행이다. 관찰은 선택 경고 6행과 설정 사본의 노출값 차이 4행이며 통과 분모에 넣지 않았다. 이 검사 수는 인수 TC 수와 다르다.

| 참조 | 자산·관계 대상, 중첩 evidence_refs, collection_ref, 탐지 대상 자산·관계 참조가 실제 출력에 존재 |

전체 JSON Schema·속성 동등성·모든 관계 종류 검증은 아니다. MAY 관계가 생성되지 않은 것을 근거·신뢰도 검증 완료로 처리하지 않는다. 필수 경고 검사는 존재와 대상을 대조하며 심각도는 expected/actual 값으로 기록한다. 합의되지 않은 선택 경고는 실패로 판정하지 않는다.

## 해석이 필요한 차이

S1-T5·S5-T1/T2/T3에서는 inventory-remote의 inventory_list_hosts/inventory_get_host 두 Tool의 원천 노출 true가 출력 null이다. 이 네 구성은 변경한 서버를 VM에서 재측정하지 않고 P2 광고 자료를 재사용한다. 어댑터가 노출을 미확인으로 낮춘 결과이며, 실제 노출이 유지된다는 근거로 원천 true를 그대로 복사하지 않는다. 차이 4행을 관찰로 보존하고 두 Tool이 실제로 null인지 별도 확인했다. 원천과 출력의 전체 상태 일치를 주장하지 않는다.

S3의 expected_no_alert는 inventory-remote Server(S1 대상)와 비충돌 Tool(S3 대상)을 함께 열거한다. S3 충돌 경고는 기대된 충돌 Tool 외에 소유 Server도 asset_ids에 포함한다. 따라서 이미 기대된 condition_id와 주 대상 Tool에 정확히 일치하는 경고는 관련 Server에 대한 금지 경고로 중복 계산하지 않았다. S5-T2 역시 명시적으로 기대된 C2 경고를 금지 경고로 세지 않는다. 원천 정답이나 탐지 코드를 수정하지 않았다.

## TC 판정 반영

| TC | 이전 | 이번 판정 | 범위 |
|---|---|---|---|
| QA-COL-03 | NOT_RUN | Pass | 동일 저장 환경·입력 3회 스캔의 자산 ID 안정성, 중복 없음, 동명 Tool별 별도 ID 확인 |
| QA-NFR-02 | NOT_RUN | Pass | 동일 저장 기준 3회 연속 실행의 자산·관계·경고 재현성 확인 |

위 두 Pass는 고정 저장 입력과 해당 코드 버전에 한정한다. VM 재수집 시 ID·재현성은 실제 연동 인수 범위에서 추가 확인한다. 나머지 TC는 전체 조건이 남아 기존 판정을 유지한다. 현재 합계는 **10 Pass·0 Fail·3 Blocked·30 NOT_RUN**이다.

스캐너 자동 테스트 실패 21개, P0 schema URL 변경 추적 차이 28건은 이번 실행의 대상이 아니므로 미해결 상태를 유지한다. 실제 VM·화면·다운로드·사용량·서버 수별 성능·0.7 전체 계약·정책·페어링 검증도 남는다.
