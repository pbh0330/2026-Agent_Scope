이 패치는 현재 GitHub 대시보드에 반영되지 않았다. 따라서 원격 원본의 문구 문제가 해결됐다고 보고하지 않는다. 제출할 대시보드에 패치를 적용한 뒤 그 commit을 제출 버전으로 기록해야 한다. 재현은 [문구 패치 생성기](prepare_minimal_copy_patch.py)와 [화면 검사기](check_dashboard_browser.cjs)를 사용한다. QA_DASH_ROOT에 검토 사본, QA_DATA_ROOT에 이번 data, QA_BROWSER_OUT에 이번 실행 폴더의 절대 경로를 지정했다.

패치 적용 사전 검사도 완료했다. 다운로드 사본의 CRLF와 패치 LF 차이 때문에 기본 git apply --check는 실패했으며 `git apply --check --ignore-space-change <패치 경로>`는 기준 8f56930 소스에서 통과했다. 적용 시에도 같은 옵션을 사용하고 파일 내용·차분을 확인한다. 패치 SHA-256과 기준 commit은 `.qa-publish/review-20261119/candidate-lock.json`에 기록했다. 이 파일은 로컬 검증 후보의 고정 기록이며 원격 제출 commit이 아니다.

처음 검토 사본 빌드는 복사된 의존성의 배포 파일 누락으로 실패했으며 npm ci로 lockfile 의존성을 재설치한 뒤 통과했다. 제품 소스를 바꾸어 빌드 오류를 숨기지 않았다.

## 보안·게시 점검의 범위

게시 대상은 QA 문서·검사 스크립트·저장 JSON·공유용 JUnit·화면 증적·Issue Form과 문서에서 참조하는 로컬 스키마/예제다. 스키마 개정본은 원격의 다른 commit으로 링크를 바꾸지 않고 stage의 docs/에 동봉했다.

work·원본 실행 로그/XML·로컬 실행 파일·가상환경·캐시·의존성·소스 ZIP·trace JSONL은 제외했다. JSON의 개인 경로와 공유 JUnit의 경로·테스트용 키 표기를 stage에서 정제하며 원천 QA 파일은 보존한다. ID·참조·정답 수를 맞추려고 바꾸지 않는다. 정제한 파일과 최종 SHA-256은 review.json/manifest.json에 기록한다.

자동 패턴 검사는 실제 비밀값이 전혀 없다는 보증이 아니다. 내부 테스트 주소·환경변수 참조는 테스트 재현 정보일 수 있다. 화면 캡처는 기존 headless 제품 화면이며 모든 이미지 픽셀을 비밀값 탐지기로 검사한 것은 아니다. 실제 운영 자격증명과 대조할 권한·자료는 없으므로 비교했다고 주장하지 않는다. 로그·다운로드 전체 비밀값 비노출 인수도 자동 Pass로 바꾸지 않는다.

## 이제 남은 필수 작업

1. 같은 실제 환경·프로필의 VM OTLP/결과 기록 위치 확보 후 실제 호출→Tool ID 매핑. 민감값을 제거한 기록을 사용하고 새 호출·비용 발생을 임의로 실행하지 않는다.
2. 원격 대시보드에 문구 최소 패치 반영 및 제출 commit 고정. 이번에 검증한 82c7579/8f56930+패치/6e4cf5c/444f558 조합과 달라지면 영향 경로 재검증.
3. 중단한 최신 Windows 회귀의 결과 확보 또는 해당 환경 제약·잔여 위험 기록. 이번 게시 준비를 전체 QA 승인으로 취급하지 않음.

범위 밖인 공통 ID 재설계·전체 0.7 전환·페어링·확대 성능 검증은 계속 후속으로 관리한다.
