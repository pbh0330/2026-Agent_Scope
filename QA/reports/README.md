## 목적별 읽는 순서

1. **현재 판정**: [실행결과](../QA_실행결과.md) → [TC 증적 연결](QA_TC증적연결_20261116.md) → 해당 실행 보고서·증적.
2. **정답 근거**: [Ground Truth](../QA_GroundTruth.md) → [원천 확인 정리](QA_GroundTruth_확인정리_20261116.md) → [정답 인덱스](../evidence/GT-20261116-444f558/index.json).
3. **실행 재현**: 해당 보고서의 고정 commit·입력·명령 → 해당 버전의 환경 정보와 실행 ID별 증적. 이전 코드와 최신 코드의 환경을 구분한다.

## 증적과 보조 스크립트

- `../evidence/RUN-*/`: 실행별 JSON 출력·로그·JUnit·검사 결과. 실제 파일은 각 보고서의 증적 링크를 따른다.
- [정답 증적 폴더](../evidence/GT-20261116-444f558/): 원천 사본 `source/`, 차분 적용 후 전체 목록 `full/`, 실행 대응표 `links/`, 출처·해시·집계 `index.json`.
- [link_ground_truth.py](link_ground_truth.py): 고정 로컬 원천 사본과 기존 실행 자료로 정답 증적을 재생성하는 보조 스크립트. 조건과 방법은 [Ground Truth](../QA_GroundTruth.md)의 재생성과 변경 관리 절을 따른다. VM 재수집이나 GitHub 최신본 갱신 명령은 아니다.

새 실행은 고유 실행 ID와 보고서·증적으로 추가하고 이 목록에 연결한다. 과거 실행 결과는 최신 코드의 결과로 덮어쓰지 않는다. 환경·최신화·원천 확인 기록을 실행 통과 증적으로 해석하지 않는다.
