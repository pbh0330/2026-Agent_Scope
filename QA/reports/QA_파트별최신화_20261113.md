## 검증 계획에 영향을 주는 내용

### 시나리오

PR #7에 실제 v2.1 규격·카탈로그·기대 결과·S2 정책이 있다. 이전의 로컬 후보 문서만으로 준비할 필요가 없다. 초기 답변에서 v2.1을 확인할 수 없다고 한 것은 로컬 자료만 확인한 한계였으며 원격 자료 확인으로 정정한다.

카탈로그의 conditions는 총 23개(S1 5, S2 5, S3 3, S4 4, S5 6)다. not_evaluated 3개(S4-C4, S5-C4, S5-C5)를 제외하면 20개이며, 이 20개에도 unknown·not_applicable 조건이 포함된다. 20개를 필수 탐지 경고 수나 실행 완료 조건 수로 사용하면 안 된다. 카탈로그의 scenario status는 draft이며 규격 문서의 담당자 확정 기록과 최종 구현 계약 합의는 구분한다.

required:false 경고는 누락 분모에서 제외하고, expected_unknown은 unknown인지 검증하며 정상으로 합치지 않는다. QA는 이 원문·정책을 고정해 기대 조건을 구체화할 수 있다.

### 테스트베드

기존 로컬 사본보다 S1-T5·S2·S3·S4·S5-T1/T2/T3 설정 및 정답, 승인 목록과 생성기 로직이 추가됐다. S2 README에는 설정이 구축 전 예상본이라고 명시되어 있다. 자료가 있다는 이유로 실제 VM 검증 완료로 처리하지 않는다. S5는 설정 사본 3개를 이용하는 정적 검증으로 VM 스냅샷 없이 진행 가능한 범위다.

S2~S4는 P2 대비 차분 정답이므로 full 목록과 구분하고 비교 전에 적용 규칙에 따라 결합해야 한다. S5-T3는 sslVerify 생략을 false로 간주하지 않고 unknown을 기대한다.

### 대시보드

HEAD는 기존 검토 기록 fac3075와 같다. 이전 `.pr13-review`에는 파이프라인 일부만 있어 이번에 UI·adapter·생성 데이터·정책 연결을 포함한 전체 사본을 확보했다. 기존 파이프라인 일부 파일과는 개행 차이도 있으므로 파일 차이를 모두 신규 기능으로 해석하지 않는다.

README의 통합 형식은 여전히 0.6.0-draft다. 스키마 0.7.0-draft와 자동 호환으로 간주하지 않는다. 기존 QA 계획의 Gateway 참조·ID 매핑·원천 17개/추가 정책 자산 범위 비교가 계속 필요하다.

### 토큰

HEAD가 과거 검토 기록 1dcf100에서 6e4cf5c로 바뀌었다. 최신 커밋은 고정분 k 배분식과 0.7.0-draft 계약의 문서 반영이다. 이전 `.pr3-review/token-collector`는 scripts 일부만 있던 사본이라 전체 backend·API·plugin·테스트·배포 자료를 이번에 확보했다. 기존 사본에 없던 파일을 모두 이번 원격 변경으로 해석하지 않는다.

usage.json과 사용량 API는 같은 계산 로직을 사용한다. 파일/API 비교, environment/profile 일치, inventory 기반 ID 연결, 병렬 배분·합계 보존을 최신 소스로 검증할 수 있다. 현재 셸 PATH에서는 go/node/npm 실행 파일이 확인되지 않아 이 단계에서 빌드·테스트를 실행하지 않았다. 별도 설치 경로 확인은 후속이다.

### 스키마·ID·QA

스키마 PR #18과 ID PR #11의 docs는 기존 로컬 파일과 비교한 범위에서 내용이 같다. 스키마 문서 v0.7.5 / 계약 0.7.0-draft 기준을 유지한다. PR #17은 병합 없이 닫혔으므로 그 브랜치를 테스트베드 최신 기준으로 사용하지 않고 develop을 사용한다.
