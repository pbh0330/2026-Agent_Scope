# QA 결함 관리 — GitHub Issues

**운영은 GitHub Issues, 보고는 QA 실행결과 문서**로 구분한다. 담당자·현재 처리 상태·수정 PR·재검증 논의는 Issue에서 관리하고, 실행 시점의 판정·측정 지표·잔여 위험은 실행결과에 기록한다. Issue가 해결되어도 과거 실행의 Fail을 Pass로 덮어쓰지 않고 별도 재검증 기록을 추가한다.

결함 보고와 최신 처리 상태는 GitHub Issue에서 관리한다. 이 문서는 심각도·처리 기준 및 Issue 작성 양식만 제공하며 별도 결함 목록을 유지하지 않는다. 결함 식별자는 Issue 번호와 URL을 사용하고 `QA_실행결과.md`에서 연결한다.

## 1. 심각도 기준

| 심각도 | 기준 | 예시 |
|---|---|---|
| Critical | 비밀값 노출, 결과 전체 손상, 검증 불가능 | 실제 토큰 출력, 정답과 무관한 데이터 대량 손상 |
| High | 핵심 시나리오 탐지 실패 또는 주요 자산·관계 누락 | 합의된 핵심 기대 경고 미탐, Node 설정 전체 누락, 동명 Tool 병합 |
| Medium | 일부 기능 오류지만 우회 또는 수동 확인 가능 | 선택 필드 표시 오류, 일부 근거 누락 |
| Low | 기능 영향이 작거나 표현·사용성 문제 | 라벨 오탈자, 정렬 불일치 |

## 2. 상태 기준

아래 상태는 팀의 처리 단계이며 GitHub 기본 상태와 구분한다. Issue 본문 또는 합의한 라벨로 단계를 기록한다. Open·Assigned·Fixed·Reopened는 재검증이 끝날 때까지 Issue를 열어 두며, Deferred는 연기 사유와 후속 계획을 기록한다. Closed·Rejected는 각각 검증 결과 또는 합의 근거를 남기고 종료한다.

- **Open**: 확인된 미해결 결함
- **Assigned**: 수정 담당자 배정
- **Fixed**: 수정 완료, QA 재검증 전
- **Reopened**: 재검증 실패
- **Closed**: 재검증과 관련 회귀 테스트 통과
- **Deferred**: 사유와 승인자를 기록하고 후속 범위로 연기
- **Rejected**: 결함이 아니라고 합의했으며 근거를 기록

## 3. 결함 등록 및 추적

1. 기존 Issue에서 같은 결함이 있는지 확인한다.
2. GitHub의 QA 결함 보고 Issue Form으로 등록하고 담당자를 배정한다. 필수 항목은 TC ID, Expected, Actual, Severity, 재현 절차, Evidence, Environment다.
3. 실행결과에 Issue 번호와 URL을 연결한다. 같은 결함이 여러 테스트에 영향을 주면 같은 Issue를 참조한다.
4. Issue에 수정 PR·commit 및 재검증 결과를 남긴다. 단순 수정 완료만으로 종료하지 않는다.

Issue 본문과 첨부 증적은 [업로드 전 민감정보 점검](README.md#github-업로드-전-민감정보-점검)을 적용한 뒤 공유한다.

## 4. Issue 본문 작성 양식

저장소 루트의 [Issue Form](../.github/ISSUE_TEMPLATE/qa-defect.yml)을 사용한다. GitHub 업로드 시 `.github/ISSUE_TEMPLATE/qa-defect.yml` 경로를 유지하고 대상 저장소의 기본 브랜치에 반영한다. 아래는 폼을 사용할 수 없는 경우에도 적용하는 작성 기준이다.

| 필수 항목 | 작성 내용 |
|---|---|
| TC ID | 관련 QA 테스트 ID. 탐색 중 발견한 결함은 미등록 사유와 후속 TC 등록 계획 |
| Expected | 합의된 기대 결과와 Ground Truth 조건 또는 기준 문서 |
| Actual | 실제 관찰 결과와 기대 결과와의 차이 |
| Severity | Critical / High / Medium / Low 중 선택 |
| 재현 절차 | 사전 조건, 입력, 수행 순서 |
| Evidence | 정제된 로그·출력·캡처의 ID 또는 링크. 미확보 시 사유 |
| Environment | OS, 구성요소 버전·commit, 프로파일, 스냅샷, 스키마·Ground Truth·시나리오 버전. 미확인·해당 없음은 사유 |
