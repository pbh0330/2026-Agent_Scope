# QA 테스트 케이스

## 1. 공통 기록 규칙

- 실제 실행 결과는 `QA_실행결과.md`에 기록한다.
- 모든 테스트는 실행한 commit, 스키마 버전 및 기준 스냅샷을 명시한다.
- 필드·상태·수집 결과 테스트는 [통합 스키마](../통합_스키마.md)의 0.2.0-draft를 준비 기준으로 한다. 실행 전 적용 문서 버전·commit과 담당자 합의를 기록하며, 미합의 조건은 확정 계약으로 판정하지 않는다.
- 결과 판정은 `Pass`, `Fail`, `Blocked`, `N/A` 중 하나를 사용한다.
- 실행 전 상태는 `NOT_RUN`(기존 표의 `미실행`)으로 기록한다. 확인된 결함은 GitHub Issue로 관리하고 실행결과에 Issue 번호·URL을 연결한다.
- `MAY_*` 관계는 정적 근거에 따른 추론이며 실제 접근·전송 사실로 판정하지 않는다.
- 실제 토큰, API key, client secret 또는 private key는 입력·출력·증적에 남기지 않는다.

## 2. S1~S5 위협 시나리오 테스트

아래 S1~S5 테스트를 계획된 필수 검증 목록에 포함한다. [위협 시나리오 후보](../위협시나리오.md)를 기준으로 준비하며, 실행 전 담당자와 문서 버전, 정상/위협 입력, 기대 경고·근거를 확정한다. 기존 QA-S1~QA-S5 테스트 ID를 유지하고 세부 조건을 갱신한다. 실행에 필요한 기준이나 환경이 없으면 `Blocked`와 사유를 기록한다.

구체적인 입력과 합격 조건은 수집 가능 범위와 담당자 합의에 따라 확정한다. 정적 결과만으로 권한 탈취·민감정보 접근·비인가 도구 실행 성공을 판정하지 않는다. 런타임 이벤트/로그 검증은 별도 범위·스키마 합의 후 추가한다.

### QA-S1-01 비인가 MCP 서버 등록 및 노출 탐지

| 항목 | 내용 |
|---|---|
| 목적 | 승인되지 않은 MCP Server가 설정에 추가되고 Agent에 노출될 가능성을 식별하는지 확인 |
| 사전 조건 | 승인된 서버만 있는 기준 스냅샷 및 승인 목록 확보 |
| 입력 | 테스트용 Skill 또는 Plugin 설정이 외부 테스트 Server를 등록하도록 변경 |
| 기대 정점 | 신규 MCP Server와 광고 자산이 각기 고유 ID로 생성됨 |
| 기대 관계 | Gateway/Node `DECLARES` Server, Skill/Plugin `ASSOCIATED_WITH` Server |
| 기대 경고 | 미승인 endpoint·출처·무결성·잠재 노출 근거를 포함한 경고 |
| 금지 결과 | 서버를 승인 서버로 오인하거나 실제 비밀값을 출력함 |
| 관련 회귀 | QA-COL-01, QA-REL-01, QA-SEC-01 |

### QA-S1-02 승인된 MCP 서버 정상 상태

| 항목 | 내용 |
|---|---|
| 목적 | 승인·고정된 서버를 비인가 서버로 오탐하지 않는지 확인 |
| 입력 | 승인된 source, endpoint, version/commit 및 정책을 가진 서버 |
| 기대 결과 | 자산과 관계는 수집하되 S1 경고는 발생하지 않음 |

### QA-S2-01 과도한 권한의 Tool 광고 탐지

| 항목 | 내용 |
|---|---|
| 목적 | 조회 도구처럼 보이지만 광범위한 파일·명령·외부 전송 입력을 가진 Tool을 식별하는지 확인 |
| 입력 | `path`, `command`, `url` 등 고위험 입력과 넓은 권한을 선언한 테스트 Tool |
| 기대 정점 | `mcp.definition`에 `description`과 `inputSchema`의 의미·구조를 보존한 정점. 민감정보가 있으면 제거를 우선하고 `redacted_fields`와 증적에 변경 위치를 기록하며 수정 없는 원본이라고 표시하지 않음 |
| 기대 관계 | Server `ADVERTISES` Tool, 근거가 있을 때만 `MAY_ACCESS` 또는 `MAY_SEND_TO` |
| 기대 경고 | 위험 입력, 권한, 승인 정책 누락 및 추론 근거 표시 |
| 금지 결과 | 실제 접근 또는 전송이 일어난 것으로 확정 표시함 |

### QA-S2-02 최소 권한 Tool 정상 상태

| 항목 | 내용 |
|---|---|
| 목적 | 제한된 입력·권한과 승인 정책을 가진 Tool을 과도한 권한으로 오탐하지 않는지 확인 |
| 기대 결과 | Tool은 수집되며 S2 고위험 경고는 발생하지 않음 |

### QA-S3-01 서로 다른 서버의 동명 Tool 충돌

| 항목 | 내용 |
|---|---|
| 목적 | 서로 다른 Server가 같은 이름의 Tool을 광고할 때 별도 자산으로 유지하는지 확인 |
| 입력 | 신뢰 Server와 테스트용 비신뢰 Server가 동일한 Tool 이름을 광고 |
| 기대 정점 | 서로 다른 `asset_id`를 가지며 각각 올바른 Server의 자산 ID를 `owner_ref`로 참조하는 Tool 정점 2개 |
| 기대 관계 | 각 Server에서 자기 Tool로 연결되는 별도 `ADVERTISES` 관계 |
| 기대 경고 | 이름 충돌 및 endpoint·공급자·권한 차이 표시 |
| 금지 결과 | 두 Tool이 하나의 정점으로 병합됨 |

### QA-S3-02 Tool 이름 충돌이 없는 정상 상태

- 입력: 서로 다른 서버가 서로 다른 이름의 Tool을 광고하는 정상 구성
- 기대 결과: 각 Tool의 ID·소유 서버·ADVERTISES 관계를 보존하고 S3 이름 충돌 경고가 발생하지 않는다.

### QA-S4-01 과도한 자격증명 공유 탐지

| 항목 | 내용 |
|---|---|
| 목적 | 여러 Server·Tool이 같은 고권한 자격증명 참조를 공유하는 상태를 식별하는지 확인 |
| 입력 | 공유 여부를 확인할 수 있는 테스트용 자격증명 참조와 권한 근거를 복수 자산에 구성. 정규화 시 `project.credential_refs[]`의 `reference_id`·`namespace` 등 합의된 필드 사용 |
| 기대 결과 | 공유 참조, scope 과다, audience 불일치 또는 미분리 상태를 경고 |
| 보안 확인 | 자격증명 유형·참조 이름만 기록하고 실제 값은 수집하지 않음 |

같은 환경변수 이름만으로 공유를 확정하지 않는다. 참조 범위와 근거를 확인할 수 없으면 미확인으로 처리한다. scope·audience 평가 필드는 담당자 합의 후 구체화한다.

### QA-S4-02 분리된 자격증명 정상 상태

| 항목 | 내용 |
|---|---|
| 목적 | 서버별 최소 권한 자격증명을 공유 상태로 오탐하지 않는지 확인 |
| 기대 결과 | 자격증명 분리 상태가 보존되며 S4 경고는 발생하지 않음 |

### QA-S5-01 안전하지 않은 원격 연결 탐지

| 항목 | 내용 |
|---|---|
| 목적 | 평문 endpoint 또는 TLS 검증 비활성화 설정을 식별하는지 확인 |
| 입력 | 테스트용 HTTP endpoint 또는 TLS 검증 비활성화 설정 |
| 기대 결과 | 위험 endpoint와 영향을 받는 Server·Tool의 연결 및 근거 표시 |
| 금지 결과 | 실제 중간자 공격 성공으로 표현함 |

### QA-S5-02 신뢰된 TLS 연결 정상 상태

| 항목 | 내용 |
|---|---|
| 목적 | HTTPS와 인증서 검증을 사용하는 승인 endpoint를 오탐하지 않는지 확인 |
| 기대 결과 | 연결 설정은 수집되며 S5 경고는 발생하지 않음 |

## 3. 자산 수집 테스트

### QA-COL-01 7종 정점 수집

- 입력: 7종 자산이 각각 하나 이상 존재하는 테스트 환경
- 기대 결과: Gateway, Node, MCP Server, Tool, Resource/Prompt, Skill, Plugin이 유형을 보존해 수집된다.
- 확인 사항: Resource와 Prompt는 `asset_subtype` 등 합의된 필드로 구분된다.

### QA-COL-02 Gateway·Node 분산 설정 수집

- 입력: Gateway와 Node 양쪽에 서로 다른 MCP Server 선언
- 기대 결과: 두 위치의 서버가 모두 수집되고 선언 위치가 보존된다.
- 실패 조건: 한쪽 설정 전체가 누락되거나 선언 주체가 뒤바뀐다.

### QA-COL-03 안정적인 복합 식별자

- 절차: 설정 변경 없이 같은 환경을 두 번 스캔한다.
- 기대 결과: 동일 자산의 ID가 유지되고 중복 정점이 생기지 않는다.
- 추가 확인: 서로 다른 Server의 동명 Tool ID는 달라야 한다.

### QA-COL-04 필수·선택 필드 누락 처리

- 입력: 선택 필드가 없고 일부 레코드에는 필수 필드가 없는 테스트 설정
- 기대 결과: 선택 필드 누락은 안전하게 처리하고, 필수 필드 누락은 해당 항목과 원인을 명확히 보고한다.
- 실패 조건: 전체 스캔이 설명 없이 종료되거나 잘못된 기본값으로 위험을 숨긴다.

### QA-COL-05 잘못된 설정 파일 격리

- 입력: 정상 설정과 구문 오류가 있는 테스트 설정을 함께 배치
- 기대 결과: 오류 위치와 원인을 기록하며 처리 가능한 다른 자산의 결과는 보존한다.

### QA-COL-06 정상 빈 목록

- 입력: 성공적으로 완료된 `tools/list`가 빈 목록을 반환하는 구성
- 기대 결과: 해당 수집은 `success`, Tool 수는 0이며 실패와 구분된다. 전체 scan 상태는 다른 수집 작업의 결과까지 반영한다.

### QA-COL-07 목록 페이지 중간 실패

- 입력: 첫 페이지는 정상이고 다음 페이지에서 시간 초과가 발생하는 목록 응답
- 기대 결과: 확보한 자산과 근거를 보존하고 해당 작업과 전체 scan을 `partial`로 기록한다. 미수집 범위·사유를 남기고 전체 목록을 수집했다고 표시하지 않는다.

### QA-COL-08 수집 실패와 자산 삭제 구분

- 입력: 이전 스냅샷에는 Tool이 있고 현재 설정 수집은 성공하지만 Tool 목록 조회는 실패하는 구성
- 기대 결과: 현재 목록 작업은 `failed`, 전체 scan은 `partial`이다. 이전 Tool을 이번에 수집한 것처럼 복사하거나 이번 누락을 삭제로 확정하지 않는다. 대시보드는 실패 범위와 이전 스냅샷을 구분한다.

## 4. 관계 및 스키마 테스트

### QA-REL-01 관계 방향과 소유 주체

- 기대 결과: `DECLARES`는 Gateway/Node에서 Server로, `ADVERTISES`는 Server에서 제공 자산으로 연결된다.
- 실패 조건: 방향이 반대이거나 자산을 참조하는 출발·도착 ID가 존재하지 않는다. Agent·접근 자원·외부 목적지 등 비정점 대상은 합의된 `TargetRef` 규칙으로 검증하며 별도 수집 자산으로 집계하지 않는다.

### QA-REL-02 추론 관계의 근거와 신뢰도

- 기대 결과: `MAY_EXPOSE_TO`, `MAY_ACCESS`, `MAY_SEND_TO`에는 합의된 evidence·confidence 정보가 있다.
- 실패 조건: 정적 추론을 실제 행위로 확정하거나 근거 없이 관계를 생성한다.

### QA-SCHEMA-01 출력 스키마 유효성

- 기대 결과: 모든 정점·관계가 합의된 형식, 자료형, 필수 필드 및 열거값을 만족한다.
- 확인 사항: 공식 MCP 정보와 프로젝트 확장 정보가 합의된 방식으로 구분된다.

### QA-SCHEMA-02 하위 호환성과 버전

- 입력: 이전에 저장한 정상 출력과 변경된 스키마 출력
- 기대 결과: 스키마 버전을 식별할 수 있고, 비호환 변경은 명시적으로 실패하거나 변환 절차를 제공한다.

### QA-SCHEMA-03 상태의 미확인·부정 판정 구분

- 입력: 정책 미확인 상태와 특정 Agent에 대한 노출 금지가 확인된 상태
- 기대 결과: 미확인은 `null`과 사유 또는 생략에 따른 unknown, 확인된 부정은 `false`와 근거·대상·정책 참조로 표현한다. 정적 출력에서 `CALLABLE`·`USED`를 true/false로 확정하지 않는다.

### QA-SCHEMA-04 계약 오류 거부와 부분 수집 수용

- 입력: 중복 ID, 없는 자산·근거·수집 작업 참조, 잘못된 TargetRef를 각각 포함한 출력 및 별도의 유효한 partial 출력
- 기대 결과: 계약 오류는 위치·원인을 알리고 거부한다. 유효한 partial 출력은 수용하고 실패 범위를 표시한다.

## 5. 보안 테스트

### QA-SEC-01 비밀값 미수집

- 입력: 환경변수와 Header가 테스트용 자격증명을 참조하는 설정
- 확인 위치: 스캐너 출력, 오류 로그, 디버그 로그, 대시보드, 다운로드 파일
- 기대 결과: 존재 여부, 유형 또는 비식별 참조만 표시된다.
- 실패 조건: 실제 값의 전체 또는 재사용 가능한 일부가 노출된다.

### QA-SEC-02 악성·비정상 광고 응답 내성

- 입력: 합의된 처리 한도를 초과하는 description, 예상하지 못한 필드, 잘못된 자료형을 반환하는 테스트 Server
- 기대 결과: 한도 초과·유효하지 않은 응답은 오류를 격리하고 보고한다. 허용된 확장 필드는 계약에 따라 처리하며 무조건 오류로 판정하지 않는다. 정상 빈 목록은 QA-COL-06으로 검증한다.

## 6. 대시보드 통합 테스트

### QA-UI-01 정점·관계 표시 일치

- 입력: Ground Truth가 확정된 스캐너 출력
- 기대 결과: 7종 정점과 관계의 종류·방향·개수가 원본 출력과 일치한다.

### QA-UI-02 동명 Tool 분리 표시

- 기대 결과: 같은 이름의 Tool을 Server별로 구분하고 소유 Server, endpoint, 권한 차이를 확인할 수 있다.

### QA-UI-03 경고 근거와 영향 경로 추적

- 기대 결과: 경고에서 관련 Gateway/Node, Server, Tool 및 탐지 근거까지 추적할 수 있다.
- 측정: 확인에 필요한 클릭 또는 탐색 단계 수를 기록한다.

### QA-UI-04 불완전 데이터 처리

- 입력: 선택 필드가 없는 유효 출력
- 기대 결과: 화면이 깨지지 않고 누락 값을 `미확인` 등 합의된 표현으로 표시한다.

## 7. 성능·재현성 테스트
