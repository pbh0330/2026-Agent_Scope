# QA 테스트 계획

## 1. 목적

자산 인벤토리 스캐너가 정의된 정적 자산과 관계를 정확하고 안전하게 수집하고, 그래프 대시보드가 그 결과와 위협 경로를 일관되게 표현하는지 검증한다.

QA는 단순 화면 확인이 아니라 다음 질문에 답하는 것을 목표로 한다.

1. 수집 대상 자산이 누락되거나 잘못 합쳐지지 않는가?
2. S1~S5 시나리오의 합의된 위험 상태를 탐지하고 정상 상태를 오탐하지 않는가?
3. 스캐너 출력과 대시보드 입력 사이의 계약이 유지되는가?
4. 비밀값을 수집·저장·표시하지 않는가?
5. 같은 환경에서 결과를 재현할 수 있는가?

## 3. 검증 범위

### 3.1 포함 범위

- 7종 정점: Gateway, Node, MCP Server, Tool, Resource/Prompt, Skill, Plugin
- MVP 관계: `DECLARES`, `ADVERTISES`, `ASSOCIATED_WITH`, `MAY_EXPOSE_TO`, `MAY_ACCESS`, `MAY_SEND_TO`
- 선언·공급망·발견·권한 계층의 정적 스냅샷
- 스캐너 출력 스키마 유효성
- 스캐너와 대시보드 간 데이터 전달
- S1~S5 중 QA 범위로 합의한 위협 상태와 대응 정상 상태
- 오류 처리, 반복 실행, 회귀 테스트
- 비밀값 미수집과 로그·화면 비노출

### 3.2 제외 범위

- 실제 공격 성공 여부를 확인하는 침투 테스트
- 공격 페이로드 실행
- 실제 Tool 호출 및 데이터 유출 검증
- `CALLABLE`, 실제 `ACCESSES`, 실제 `SENDS_TO` 확정
- 모델 자체 취약점과 Prompt Injection 탐지 모델 평가
- 런타임 토큰 소비 이상 탐지(후속 범위로 관리)

## 4. 역할 및 협업 지점

| 영역 | 주 담당 | QA 확인 사항 |
|---|---|---|
| QA·테스트베드 검증 | 정서진 | 합격 조건, 테스트 케이스, 결과 및 결함 관리 |
| 자산 식별 스캐너 | 김규민 | 정점·관계·필드 수집 결과와 오류 처리 |
| 그래프 대시보드 | 고혜림 | 스키마 수용, 자산·관계·경고 표시 |
| 토큰 사용량 수집 | 이정철 | 데이터 확보 가능 범위와 후속 런타임 지표 |
| 테스트베드 구축 | 박병하 | 2대 구성, 기준 스냅샷, 재현 환경 |

공통 데이터 스키마, 스캐너 출력, 대시보드 입력 또는 모듈 간 인터페이스가 변경되면 관련 담당자와 합의하고 영향받는 테스트를 다시 수행한다.

위협 시나리오 작성·확정은 시나리오/대시보드 담당 파트에서 수행한다. 현재 S1~S5를 계획된 필수 시나리오로 삼는다. QA는 확정 문서·버전, 정상/위협 구성, 기대 경고·근거와 제공 데이터를 인수해 각 테스트의 세부 검증 조건을 확정한다. 런타임 이벤트/로그 검증은 스키마·데이터 제공 방식·검증 범위 합의 후 추가한다.

## 6. 진입 및 종료 기준

### 6.1 진입 기준

- [ ] 테스트할 PR 또는 commit이 식별되어 있다.
- [ ] 출력 스키마 버전과 필수 필드가 합의되어 있다.
- [ ] Gateway·Node 기준 스냅샷이 확보되어 있다.
- [ ] 정답 자산·관계·경고 목록이 작성되어 있다.
- [ ] 테스트용 비밀값은 실제 운영 자격증명과 분리되어 있다.
- [ ] 실행 방법과 로그·출력 위치를 알고 있다.

### 6.2 종료 기준

시나리오 관련 테스트는 확정 문서와 기대 조건을 인수한 뒤 실행한다. 기준 미확정으로 실행할 수 없으면 `Blocked`와 사유를 기록한다. 공통 테스트는 자체 사전 조건 충족 시 실행할 수 있다.

- [ ] 계획된 필수 테스트를 모두 실행했다.
- [ ] 보안 및 데이터 무결성 관련 Critical·High 결함이 없다.
- [ ] 실패 테스트가 수정되었거나 잔여 위험으로 명시적으로 승인되었다.
- [ ] 수정 기능의 재검증과 관련 회귀 테스트를 완료했다.
- [ ] 수집 정확도·오탐·시나리오 기대 조건 충족률·소요 시간을 기록했다.
- [ ] 실행 환경, 결과 및 증적만으로 다른 팀원이 재현할 수 있다.

## 7. 측정 지표

| 지표 | 계산식 | 목표치 |
|---|---|---|
| 자산 수집 재현율 | 올바르게 수집된 자산 수 / 정답 자산 수 | 기준 실행 후 합의 |
| 수집 자산 중 오탐 비율 | 정답에 없는 수집 자산 수 / 전체 수집 자산 수 | 기준 실행 후 합의 |
| 관계 정확도 | 올바른 관계 수 / 출력된 전체 관계 수 | 기준 실행 후 합의 |
| 시나리오 기대 조건 충족률 | 충족한 기대 조건 수 / 실행한 합의된 기대 조건 수 | 조건 목록 확정 후 합의 |
| 정상 환경 오탐 수 | 정상 상태에서 발생한 부당 경고 수 | 기준 실행 후 합의 |
| 수집 소요 시간 | 스캔 시작부터 유효 출력 완료까지 | 서버 수와 함께 기록 |
| 가시화 탐색 단계 | 경고에서 영향 자산·경로 확인까지의 클릭 또는 단계 수 | 기준 실행 후 합의 |

분모가 0인 지표는 0으로 계산하지 않고 `N/A`로 기록한다.

선언 계층(`declared`)과 광고 계층(`advertised`)의 수집 재현율도 각각 기록한다. 비교 대상 프로파일·스냅샷·수집 범위·인증 맥락을 맞추고, 계층 간 중복 자산은 전체 집계에서 중복 계산하지 않는다. 부분 수집 시 누락과 수집 실패 범위를 함께 보고하며 누락을 자산 삭제로 단정하지 않는다.

테스트베드 인수 시 P0는 기본 수집, P1은 분산 수집, P2는 7종 자산 검증에 연결한다. 위협 구성은 기준 프로파일과 변경분의 적용 규칙을 확인한다. SNAP-1의 “0건”은 MCP 서버 등 대상 유형별로 확인하고 Gateway·Node를 포함한 전체 자산 0건으로 가정하지 않는다.

## 8. 우선순위

1. 비밀값 노출 및 결과 무결성 검증
2. 공통 자산·관계 수집 및 스키마 검증
3. S1~S5의 합의된 위험 상태·정상 대조 검증
4. 대시보드의 자산·경고·근거 연결 확인
5. 성능·사용성 및 후속 런타임 항목

## 9. PR QA 체크리스트

- [ ] Issue의 완료 조건과 구현 결과가 일치한다.
- [ ] PR에 관련 Issue, 변경 내용, 테스트 방법, 리뷰 주의사항이 있다.
- [ ] 변경된 기능의 정상·실패·경계 테스트가 있다.
- [ ] 기존 기능에 대한 회귀 테스트 결과가 있다.
- [ ] 스키마 변경 시 버전, 영향 범위 및 담당자 합의가 기록되었다.
- [ ] 비밀값 또는 민감한 로컬 경로가 출력·로그·화면에 노출되지 않는다.
- [ ] `develop` 반영 결과를 다시 확인한 뒤 Issue를 종료한다.
